# PRD: 合并 coros 到 article-collector

## 概述

将 coros 运动截图识别功能合并到 article-collector，实现统一的信息收集入口。

## 问题/动机 (Pain)

- 当前有两个独立的飞书机器人（article-collector 和 coros），入口分散
- 两套代码库维护成本高
- 未来扩展其他信息类型时，难以统一管理
- 用户需要记住不同机器人的用途

## 目标 (Goal)

- 统一代码库：coros 功能迁移到 article-collector
- 统一入口：一个机器人处理所有类型的信息（文章、想法、运动截图）
- 智能分发：根据图片内容自动识别并分发到对应处理逻辑
- 保持兼容：现有功能不受影响

## 功能需求

### 1. 图片消息分类

当用户发送图片时，自动识别图片类型：
- **运动截图**（COROS/Garmin 等）→ 走运动记录处理逻辑
- **小红书截图** → 现有 OCR + 想法处理逻辑
- **其他图片** → 现有 OCR 处理逻辑

### 2. 运动截图处理（从 coros 迁移）

- OCR 识别运动数据（日期、类型、距离、爬升、时长）
- 交互卡片让用户确认/编辑
- 写入运动记录多维表格
- 去重机制

### 3. 配置项

新增以下配置（可选，未配置则不启用运动功能）：
- `COROS_BITABLE_APP_TOKEN` - 运动记录表 app_token
- `COROS_BITABLE_TABLE_ID` - 运动记录表 table_id
- `COROS_FIELD_*` - 字段映射
- `COROS_ENABLED` - 功能开关

## 用户故事

1. 作为用户，我发送一张 COROS 运动截图，机器人自动识别为运动记录，弹出确认卡片
2. 作为用户，我发送一张普通截图，机器人按原有逻辑进行 OCR 处理
3. 作为用户，我不需要关心该发给哪个机器人

## 验收标准 (Done Criteria)

- [ ] 发送 COROS 运动截图，能被正确识别并处理
- [ ] 发送普通图片，走原有 OCR 流程
- [ ] 发送文章链接，功能正常（回归测试）
- [ ] 发送纯文字，想法记录功能正常（回归测试）
- [ ] 小红书链接处理正常（回归测试）
- [ ] 配置项缺失时，运动功能优雅降级（不报错）

## 影响范围

### 新增文件
- `src/services/coros-handler.ts` - 运动截图处理核心逻辑
- `src/services/coros-ocr-parser.ts` - 运动数据解析（从 coros 迁移）

### 修改文件
- `src/config.ts` - 新增 coros 相关配置
- `src/handlers/message.ts` - 添加图片消息分类逻辑
- `src/handlers/card-action.ts` - 添加运动记录卡片回调处理
- `.env.example` - 新增配置示例

## 风险点

| 风险 | 应对措施 |
|------|----------|
| 图片分类不准确 | 先用关键词规则，后续可加 AI 分类 |
| OCR 识别失败 | 降级到手动输入卡片 |
| 原有功能受影响 | 充分回归测试 |

## 不在范围内 (Out of Scope)

- 周报功能（暂不迁移）
- AI 智能分类（后续版本）
- 新建数据库（使用现有表）

## 技术方案概要

```
用户发送图片
    ↓
handlers/message.ts 接收
    ↓
图片分类（OCR + 关键词）
    ↓
┌─────────────────┬─────────────────┐
│  运动截图        │  其他图片        │
│  (coros-handler) │  (现有 OCR 流程) │
└─────────────────┴─────────────────┘
    ↓                    ↓
运动记录多维表格      素材库/想法库
```
